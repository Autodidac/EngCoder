ThreadSpire 0.5.6 validation
=============================

Observed failure
----------------
The clean generation initialized successfully, then automatic bootstrap failed
with:

  AttributeError: 'str' object has no attribute 'is_file'

Root cause
----------
The 0.5.5 curriculum guard globally wrapped argparse and replaced argparse's
pathlib.Path value for --seed-dataset with a plain string. The internal data
loader then called .is_file() on that string. The same broad field-name logic
also risked treating unrelated --module filesystem paths as training targets.

State interpretation
--------------------
A generation reported as g000000 / initialized-untrained / 0 verified target
tokens / external base weights none is the fresh random English-lineage model.
0.5.6 retains and trains it; another reset or quarantine pass is not required.

Corrective changes
------------------
1. Removed global argparse monkey-patching.
2. model_worker.py explicitly invokes the curriculum guard after parsing.
3. The guard applies only to train-internal.
4. Filtered dataset replacements preserve pathlib.Path values.
5. The training loader defensively converts Path|string inputs to Path.
6. english-foundation maps to the concrete english-core internal expert.
7. Bootstrap records, accumulated episodes, and held-out anchors are
   English-only before the gate.
8. The loader independently rejects explicit or code-shaped C++ records while
   the optimizer scope is English.
9. Promoted English generations persist state/curriculum-state.json.
10. C++ unlocks only after English evaluation passes and bootstrap completes.
11. Unrelated command paths, including --module, are never rewritten.
