      Model Library

      EngCoder-native model runtimes. Download or import weights, load/unload them, then assign one as KeyMaker without changing LM Studio, Bionic, or the internal learned models.

      Adding your own models · what EngCoder hosts

      EngCoder can register and download compatible Hugging Face GGUF weights, or use a GGUF file already on the host PC. Enter its repository/quant or local path below, save the profile, then use Download and Load on the model card. Saved model profiles persist across updates.

      Current limitation: the native runtime hosts one active GGUF at a time. Your small 9B and middle 27B models can run together with KeyMaker through an OpenAI-compatible local provider such as LM Studio. This is HTTP model inference, not an MCP server. Assign them once under System 1 Architect + KeyMaker.

      Native simultaneous 9B → 27B → KeyMaker hosting is tracked as a separate engineering mission; it needs per-model ports, compatible llama.cpp options, memory budgets, and verified crash/restart handling. Loading extra large models without those limits is not enabled silently.

      System 1 Architect + KeyMaker

      Architect classifies each request and chooses the fastest safe route. KeyMaker is the large model that owns difficult answers, coding, tools and final verification.

      Three-model setup — where external models come from and when they run

      1. Load models in LM Studio on the host computer. In LM Studio, download a lightweight model and a different medium-size model. Start LM Studio's local OpenAI-compatible API server (commonly port 1234). EngCoder connects to that API; it does not download or load those weights itself.

      2. Connect EngCoder. EngCoder connects from its server computer to LM Studio at http://127.0.0.1:1234 by default. The host endpoint is configured at startup using ENGCODER_MODEL_SERVER_URL (or ENGCODER_LMSTUDIO_URL), not the Session Settings browser endpoint. Reload EngCoder after changing its server URL. Choose Refresh here to discover available external models. In served Web mode, LM Studio still runs on the host, not on the browser's machine.

      3. Assign roles. Leave internal Qwen as KeyMaker; choose the lightweight model under Small and a different model under Middle. The Assign button fills these roles without replacing KeyMaker. Optional specialist selectors can use additional external models; without one, small-model checklists fill in automatically.

      4. Use it. Automatic routing sends safe greetings to Small, routes coding and complex tasks through bounded specialist preparation and Middle review, and leaves final decisions to KeyMaker. Math, numerical proofs, security and other reliability-sensitive requests go straight to KeyMaker. Run info shows which stages actually ran; Output remains just generated text.

      5. Understand failures. Missing external model or refused request causes a stage failure, then KeyMaker proceeds when safe. This is advisory delegation, not independent code execution by subagents. GPU offload below applies only to native Qwen.
